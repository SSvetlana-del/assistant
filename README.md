# IT Навигатор — AI-консультант образовательной платформы

Тестовый проект для портфолио продакт-менеджера. Чат имитирует поддержку IT Навигатора: помогает подобрать обучение, отвечает на вопросы об условиях и сопровождает запись.

Стек: Gradio, LangGraph, LangChain/GigaChat, Pydantic, Supabase PostgreSQL. SQLite используется для локальной разработки.

## Каталог

В `data/courses.json` — 17 программ по тестированию, аналитике данных, системной, продуктовой и бизнес-аналитике, управлению проектами и продуктом, дизайну.

Каждая карточка содержит название, направление, уровень, стоимость полного курса, продолжительность, примерную нагрузку в неделю, три даты старта, формат, требования и темы.

Цены и расписание — вымышленные фиксированные данные для демонстрации продукта. Для начинающих стоимость составляет 4000–15000 ₽, для продвинутых — 12000–45000 ₽. SQL стоит 4000 ₽, старт — 01 декабря 2026 года. Ссылок на сторонние источники в карточках и ответах нет. Описание проекта редактируется в поле `notice`.

## Поведение чата

- Цена: ответ формируется из карточки, без генерации чисел моделью. Например: «Интерактивный тренажер по SQL — 4000 ₽. Обучение начнется 01 декабря 2026 года. Хотите записаться?»
- Если курс не выбран, консультант уточняет, какая программа интересует.
- Выбор: консультант уточняет цель, опыт и время, предлагает до двух программ с условиями и объясняет выбор.
- Общие вопросы: короткий ответ по условиям платформы и уместный дополнительный вопрос.
- Запись полностью в чате: ассистент уточняет курс, дату старта, имя и контакт (email или телефон), показывает сводку и ждёт явного подтверждения. Только после этого запись сохраняется. Сводку можно изменить или отменить. В чате появляется сообщение о передаче заявки менеджеру, который свяжется в течение рабочего дня. Скачивания нет; уведомления менеджеру пока не подключены.
- Память: история хранится в PostgreSQL; модели передаются последние 30 сообщений. Возвращайтесь в том же браузере, чтобы продолжить диалог.

Демо не принимает оплату и не выдаёт реальный доступ к обучению. Текст об этом остаётся в описании проекта.

## Запуск

Нужен Python 3.12:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
cp .env.example .env
# Добавьте свой GIGACHAT_CREDENTIALS, затем:
python app.py
```

Ключ авторизации GigaChat хранится только на сервере. Для облачного размещения задайте DATABASE_URL и BROWSER_SECRET в секретах Render. Инструкции: `SUPABASE.md`, `RENDER.md`. TLS-проверка включена, официальный доверенный корневой сертификат GigaChat хранится в `certs/`.

## Паттерны

| Паттерн | Где применяется |
|---|---|
| Router | LangGraph в `advisor/engine.py` выбирает ветку цена/сравнение/подбор/общее/запись. |
| Strategy | Для каждой ветки заданы собственные правила ответа. |
| Structured output | Pydantic проверяет интент и ID курсов. |
| Grounded generation | Модель отвечает по актуальному JSON; старые цены из истории не считаются источником фактов. |
| Repository | `advisor/storage.py` отделяет базу данных от UI и модели. |
| Human in the loop | Запись выполняется только после явного подтверждения в чате. |
| Idempotent command | Транзакции, одноразовый токен и уникальность записи защищают от дублей. |

## Проверки

```bash
pip install pytest
python -m pytest -q
```

Проверяются маршрутизация, диалог, цены и диапазоны, расписание, запись, защита от дублей и совместимость старых подтверждений. Интеграционные тесты PostgreSQL запускаются только с TEST_POSTGRES_URL, указывающим на отдельную временную БД, а не на Supabase пользователя.


## Сценарий записи и интерфейс

`advisor/booking.py` — детерминированный автомат состояний: курс → дата → имя → контакт → подтверждение. Состояние сохраняется вместе с диалогом, поэтому обновление страницы не сбрасывает незавершённую запись. Явное подтверждение распознаётся только на последнем шаге; модель не получает доступ к команде записи. Изменение данных инвалидирует прежний черновик. Отмена и повторное подтверждение не создают дублей.

Для заявки нужны курс, выбранный старт, имя и email или телефон для связи. Нагрузка используется только как фильтр каталога и при подборе. В новых записях поля preferred_load нет; ранее созданные записи сохраняются.

Новый интерфейс: фирменный чат, быстрые вопросы, кнопки подтверждения в диалоге, каталог с фильтрами по направлению, уровню и времени на учёбу. `assets/theme.css` задаёт оформление и мобильную компоновку. Иллюстрация `assets/navigator.svg` создана для этого проекта. HTML-язык зафиксирован как русский до и после инициализации Gradio.


### Программы и точность консультации

У всех 17 демонстрационных курсов в `data/courses.json` заданы описание, аудитория,
входные знания, модули, инструменты, практический проект, результаты и ограничения.
Это авторские программы учебной платформы, а не описание услуг реальных школ.
Карточки раскрывают программу через «Программа и результат»; тот же каталог
используется для ответов о содержании курса.

`advisor/guidance.py` задаёт правила намерений и извлечения контекста. Запись можно
начать по явной просьбе или короткому согласию непосредственно после предложения
записаться; одного решения LLM недостаточно. Вопросы об оплате отвечают по политике
учебного проекта без перезапуска заявки. Смена курса прекращает только
неподтверждённый черновик, подтверждённые записи сохраняются.

В узле `selection` LangGraph применяются фильтры направления, уровня, времени и
бюджета. Результаты не расширяются курсами из других направлений. В узле `general`
программы и правила оплаты выводятся из данных без генерации, остальные вопросы
передаются GigaChat с ограниченным контекстом. Проверки в
`tests/test_support_regressions.py` воспроизводят проблемный диалог поддержки.


### Контакт и заявка менеджеру

`advisor/contact.py` проверяет формат одного email или телефона и нормализует
телефон. Это проверка формата, а не подтверждение владения контактом. Контакт
показывается в сводке; пользователь может изменить его или отменить заявку.
Незавершённые старые сводки без контакта переводятся на шаг его ввода.

После явного подтверждения в `enrollments.payload` сохраняются `contact_type`,
`contact_value`, `status: pending_manager`, `handoff_channel: manager_queue` и
`notification_status: not_configured`. Это очередь заявок для менеджера в Supabase,
без отправки писем или сообщений. Реальная обработка менеджером не автоматизирована;
обещание связи в течение рабочего дня — часть демонстрационного сценария.

Для просмотра контактов владелец использует закрытую схему `it_advisor` в Supabase.
Публичного списка заявок и скачивания файлов в приложении нет. Ранее подтверждённые
записи сохраняются. Если старая запись ещё не содержит контакта, новое подтверждение
полной сводки дополняет её без дублирования номера заявки.


### Сравнение и рекомендации по дизайну

Узел `comparison` в LangGraph отдельно обрабатывает сравнение программ. Если
направление неизвестно, ассистент спрашивает его; ответ «по дизайну» продолжает
сравнение. Таблица показывает цель, аудиторию, требования, практику, стоимость,
нагрузку и дату старта. Указанные пользователем пары курсов сохраняются, даже если
их названия относятся к одному направлению. Сравнение не запускает запись.

Для дизайна персональный подбор дополнительно уточняет цель: создание интерфейсов,
продуктовый подход или исследования пользователей. `UX-исследования` остаётся
продвинутой специализацией с явно указанной базой в цифровых продуктах и
пользовательских сценариях. Курс отображается в сравнении, но не рекомендуется
автоматически всем, кто выбрал дизайн. Если начинающему нужен курс по исследованиям,
ассистент сообщает об отсутствии начальной программы вместо подмены её UI-дизайном.

### Ожидание ответа и готовый текст поддержки

Системный прогресс Gradio отключён через `show_progress='hidden'` у событий;
текст таймера скрыт отдельно, сообщения об ошибках сохраняются. Пока выполняется
запрос, в шапке чата отображается «Готовлю ответ…». После ответа или ошибки статус
и элементы управления возвращаются в обычное состояние.

`advisor/replies.py` удаляет служебные подписи вопросов и повторные соседние вопросы
в конце ответа. Очистка применяется к генерации и к отображению старых ответов,
не изменяя исходную историю и пользовательские сообщения в базе.
