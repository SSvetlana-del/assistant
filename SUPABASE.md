# Supabase + Render

Архитектура: Render запускает Gradio и GigaChat; Supabase PostgreSQL хранит диалоги, черновики и подтверждённые записи. Каталог курсов остаётся версионируемым JSON-файлом. Supabase Auth, Storage и Data API этому прототипу не нужны.

## Создать проект

1. Откройте https://supabase.com/dashboard и войдите в аккаунт.
2. Создайте организацию, если её ещё нет, затем **New project**.
3. Название: `it-navigator`. Выберите доступный бесплатный план. Платный план для этой конфигурации не требуется.
4. Задайте случайный пароль БД и сохраните его в менеджере паролей. Не отправляйте пароль в чат и не добавляйте его в Git.
5. Выберите регион рядом с Render-сервисом и дождитесь готовности проекта.
6. В проекте нажмите **Connect → Session pooler**. Этот режим подходит для IPv4-подключения серверного Python-приложения. Скопируйте PostgreSQL connection string и подставьте пароль. Зарезервированные символы пароля должны быть URL-encoded.

Пример только формата, не рабочие реквизиты:

```text
postgresql://postgres.PROJECT_REF:PASSWORD@POOLER_HOST:5432/postgres?sslmode=require
```

Нужна именно строка PostgreSQL, не Project URL, не anon key и не service_role key.

## Подключить к Render

В Environment сервиса задайте:

- `DATABASE_URL`: секретная строка Session pooler.
- `GIGACHAT_CREDENTIALS`: ключ авторизации GigaChat.
- `BROWSER_SECRET`: постоянная случайная строка. При создании Blueprint генерируется Render автоматически.

Сохраните переменные и выполните deploy. `render.yaml` требует DATABASE_URL при первом создании. Для существующего Blueprint новый секрет нужно добавить вручную в Environment, поскольку `sync: false` не запрашивает новые значения при обновлении.

При первом старте приложение создаёт схему `it_advisor` и три таблицы: `sessions`, `drafts`, `enrollments`. Данные находятся вне `public`; RLS включён, клиентских политик нет, браузер напрямую к базе не подключается. Используется серверное соединение владельца БД. **Не добавляйте `it_advisor` в exposed schemas Data API.**

При ошибке подключения на Render приложение останавливается, а не переключается незаметно на временную SQLite. TLS включён по умолчанию; при наличии CA можно усилить проверку через `sslmode=verify-full` и `sslrootcert` в строке соединения. `sslmode=require` шифрует соединение, но сам по себе не проверяет имя сервера.

## Проверить

1. Отправьте два сообщения, обновите страницу: история должна восстановиться.
2. Оформите запись, скачайте TXT-подтверждение.
3. Перезапустите Render-сервис: история и запись должны остаться в том же браузере.
4. Повторите запись на тот же курс: приложение должно вернуть существующую запись, а не создать дубль.

SQLite остаётся локальным режимом, если DATABASE_URL не задан и приложение не запущено на Render. Данные из старой SQLite автоматически в Supabase не переносятся. Файл подтверждения временный: скачайте его после записи; запись в PostgreSQL сохраняется отдельно.

## Тестирование без облачных аккаунтов

Интеграционные тесты используют только отдельную временную PostgreSQL, не Supabase пользователя:

```bash
docker run --rm -d --name advisor-test -e POSTGRES_HOST_AUTH_METHOD=trust -e POSTGRES_DB=advisor -p 127.0.0.1:55432:5432 postgres:17-alpine
TEST_POSTGRES_URL='postgresql://postgres@127.0.0.1:55432/advisor?sslmode=disable' python -m pytest -q
docker stop advisor-test
```

`trust` и `sslmode=disable` допустимы только для этой одноразовой локальной БД. Для Supabase используйте пароль и TLS. При отсутствии TEST_POSTGRES_URL интеграционные тесты пропускаются.

Документация подключения: https://supabase.com/docs/guides/database/connecting-to-postgres .
